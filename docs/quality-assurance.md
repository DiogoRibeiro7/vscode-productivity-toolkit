# Quality Assurance Playbook

The **VS Code Productivity Toolkit** ships with an automated quality program that ensures every contribution remains production-ready across supported platforms.

## Test Coverage

| Area | Tooling | Scope |
| ---- | ------- | ----- |
| Unit Tests | `pytest` | Python CLI modules, installer logic, utility helpers |
| Installation Scripts | Bash, PowerShell, Python smoke tests | Validates dry-run execution across shells |
| Extension | Manifest validation | Ensures Smart Task Detector activation rules and commands remain intact |
| Documentation | Markdown scanners | Confirms fenced code blocks declare languages and relative links resolve |
| Performance | Benchmarks | Guards task loading within a one-second latency budget |

## Compatibility Matrix

| Platform | Python | Node.js | Status |
| -------- | ------ | ------- | ------ |
| Windows 11 | 3.8–3.12 | 18, 20 | ✅ Manual validation via GitHub Actions matrix |
| macOS 13 | 3.8–3.12 | 18, 20 | ✅ Automated coverage |
| Ubuntu 22.04 | 3.8–3.12 | 18, 20 | ✅ Automated coverage |

> **Note:** Automated CI spans Ubuntu, macOS, and Windows runners. Additional ARM coverage is executed on-demand prior to releases.

## Security & Compliance

- **Python:** [Bandit](https://bandit.readthedocs.io) scans `toolkit/`, `scripts/`, and `qa/` modules for insecure patterns.
- **JavaScript:** `npm audit --production` enforces dependency hygiene inside the Smart Task Detector extension.
- **Shell:** `shellcheck` (on Linux/macOS runners) validates POSIX compliance for `install.sh`.
- **Documentation:** `codespell` prevents regressions in copy, while Markdown linting is provided through the VS Code workspace configuration.

## Documentation Validation

Documentation quality gates ensure:

- Each fenced code block specifies a language for syntax highlighting and accessibility.
- Relative links resolve to local resources, preventing navigation dead ends.
- Example command sequences embedded with `<!-- qa:commands=... -->` annotations can be executed locally for reproducibility.

Run the Markdown checks locally:

```bash
python -m pytest tests/test_documentation_quality.py -vv
```

## Performance Benchmarks

The benchmark suite keeps average task loading under **500ms** on commodity developer workstations. Execute benchmarks with:

```bash
python -m pytest tests/test_performance_benchmarks.py -vv
```

## Continuous Integration

Refer to [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) for the complete automation pipeline. The workflow orchestrates:

1. Multi-platform test matrices (Ubuntu, macOS, Windows).
2. Unit, integration, and benchmark execution.
3. Security scanning (`bandit`, `npm audit`).
4. Documentation validation (`codespell`, Markdown link checking).
5. Build verification for the Smart Task Detector extension.

## Manual Verification Checklist

Before publishing a release:

1. Review `pytest --maxfail=1 --disable-warnings -vv` results across platforms.
2. Confirm `bandit -r toolkit scripts qa` reports no high-severity findings.
3. Execute `npm audit --prefix extensions/smart-task-detector` and resolve vulnerabilities.
4. Validate documentation by running the Markdown quality tests.
5. Inspect release notes generated by `semantic-release` to ensure accuracy.

Adhering to this playbook keeps the toolkit secure, maintainable, and delightful for contributors worldwide.
